## A. Protecciones que parecen funcionar y no funcionan (seguridad)

- **A1 · crítico · NECESARIO — Los hooks se caen con Python 3.9 y `barreras` queda abierta.** [V] Con `/usr/bin/python3` (3.9.6, el de macOS; también Amazon Linux 2023) `barreras.py`, `revisar_al_terminar.py`, `ruff_al_editar.py` y `evaluador_bloqueado.py` salen con 1 (`TypeError` por anotaciones `str | None`). Exit 1 es error no bloqueante: la acción sigue. Igual `verify.py`, `deuda.py`, `suministro.py`, `mutantes_del_diff.py`, `adoptar.py` [A]. Un PATH mínimo de macOS resuelve `python3` → 3.9.6 [V].
  Arreglo: `from __future__ import annotations` en todos; versión mínima en CONVENCIONES; `"onFailure": "block"` en barreras (Claude Code ≥ 2.1.295; instalado 2.1.319) [D]; prueba que corra los hooks con 3.9 o `ruff --target-version py39 --select FA102`.
- **A2 · crítico · NECESARIO — La SCP "sin escritura vía MCP" no deniega nada.** [V] usa `Bool aws:CalledViaAWSMCP`; la política de identidad usa `aws:ViaAWSMCPService`. [A] según AWS, `CalledViaAWSMCP` es String (`aws-mcp.amazonaws.com`): la condición nunca se cumple. Arreglo: `Bool aws:ViaAWSMCPService` + validar con Access Analyzer `--policy-type SERVICE_CONTROL_POLICY`.
- **A3 · importante · NECESARIO — El kit no frena borrados locales.** [V] barreras deja pasar `rm -rf src`, `git reset --hard`, `git push --force origin main`, `git clean -fdx`. Hoy los frena tu hook global `~/.claude/hooks/block-destructive-bash.py` (no es del kit; el equipo no lo tiene; la limpieza del pendiente 2 no lo menciona). Ninguno frena `git commit --no-verify`. Al pasarlo al kit, usar el análisis de barreras (no bloquea cuando no entiende comillas; el hook global bloqueó comandos válidos de dos agentes por eso).
- **A4 · importante · NECESARIO — La plantilla de permisos solo niega el `.env` de la raíz.** [D] `Read(.env)` o `Read(**/.env)` cubren cualquier profundidad; `Read(./.env)` es relativo al directorio actual. Con la regla correcta Claude Code bloquea también destinos de redirección (`cat < .env`) [D]; para scripts, `sandbox.filesystem.denyRead`. Corregir `plantillas/claude/settings.json`, README de barreras y `settings-permisos-aws.json`; agregar `.envrc`.
- **A5 · importante · NECESARIO — El perfil SSO "exclusivo" del agente no lo aísla.** [A, doc AWS CLI] Perfiles con la misma `sso_session` comparten el token: el agente puede usar `--profile <otro con escritura>`. Arreglo: abrir Claude con credenciales temporales del rol de lectura (`aws configure export-credentials --profile agente-dev-ro --format env`); completar el bloque `[sso-session]`.
- **A6 · importante · NECESARIO — `--skip-auth` de aws-core no significa "sin credenciales".** [A, README del proxy] Si hay credenciales, firma igual; los MCP corren fuera del sandbox [D]. Corregir aws-acceso-agente y AUDITORIA; modo solo-docs con `AWS_CONFIG_FILE=/dev/null` y `AWS_SHARED_CREDENTIALS_FILE=/dev/null`.
